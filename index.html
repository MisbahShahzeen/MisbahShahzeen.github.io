Claims Intelligence

Complete

Event-driven insurance claims processing platform

Four services — claims-api, outbox-relay, ingestion-worker, decision-worker — move a claim through an eight-state machine. The state machine is a pure function with no I/O and its transition table is expressed as data, so the tests enumerate every legal move rather than sampling a few. Messaging between services goes through a transactional outbox with idempotent consumers and a dead-letter queue, whose routing I verified against a real poison event.

Document extraction and assessment run on Gemini 2.5 Flash; precedent retrieval uses two HNSW pgvector collections and scores 0.79–0.81 at rank one. Authentication defends against user enumeration by hashing a dummy password on unknown emails, and approvals above an authority limit require a second reviewer.

What I'd talk about in an interview: Alembic's autogenerate silently proposed dropping both HNSW indexes on every migration — they aren't expressible in ORM metadata, so nothing would have errored. The queries would just have degraded to sequential scans.

CareerLens

Complete

AI-assisted résumé and job-matching tool

RAG analysis took 267 seconds against a 120-second inter-service HTTP timeout, so the fix had to be structural rather than a longer timeout: the AI work moved out behind an async job queue with a two-replica worker, and the frontend polls job status instead of holding a request open. Embeddings are 768-dimensional and stored in pgvector, with cosine thresholds tuned for match quality; the data layer is SQLAlchemy with Alembic migrations and Redis-backed rate limiting in front.

The frontend is live on Vercel. The backend deployment is currently paused, so the hosted demo is frontend-only — the full stack runs from the repo.
